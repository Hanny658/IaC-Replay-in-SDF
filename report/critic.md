**这轮最重要的发现，是性能收益主要来自 rotation，而 isolation 的边际精度收益较小。**

新版表 1 给出了很清楚的四组合：

| Rotation | Isolation | Sequential accuracy |
| -------- | --------- | ------------------: |
| 无        | 无         |                87.0 |
| 无        | 有         |                88.8 |
| 有        | 无         |                92.1 |
| 有        | 有         |                92.7 |

由此得到：

* 没有 rotation 时，isolation 增加 **1.8** 个百分点。
* 没有 isolation 时，rotation 增加 **5.1** 个百分点。
* 已有 rotation 时，isolation 再增加 **0.6** 个百分点。
* 已有 isolation 时，rotation 再增加 **3.9** 个百分点。

这让论文的解释更可信。它支持一个更明确的结论：**rotation 承担主要精度收益；isolation 提供有条件的当前隐藏计算不变性，并在所测 batch 8–16 配置下带来较小的额外收益。**

**1. 全文仍残留旧版对 isolation 的归因。**

第 8 页第 307 行写：

> “Its accuracy value is large without rotation (−5.7 points) …”

这里如果指 isolation，数字应当是 **1.8**，而不是 5.7。5.7 是完整方法与“两者都没有”的差距。

类似问题还出现在：

* **图 5**：约 `(87.0, 96.1)` 的点仍标为 `−isolation`，实际对应 `−isolation, −rotation`。
* **第 6 页 replay gain 讨论**：`92.7 masked` 与 `87.0 unmasked` 仍同时改变了 rotation。这个 sweep 可以说明旧的无 rotation 对照没有被固定 replay gain 明显压低，但不能用于估计 isolation 单独的贡献。
* **摘要**：突出“unmasked replay without rotation”退化，却没有交代“rotation + unmasked replay”已经达到 92.1。读者仅看摘要，仍可能高估 isolation 对精度的必要性。

**这不是要求增加更多实验，而是让现有实验决定全文的表述。**

**2. “Guarantee”需要保持条件性，摘要中的端到端表述仍偏强。**

这版新增三种子隐藏表示变化率和 logit 变化幅度，是有效改进。附录 I 也报告了 raw CIFAR-10 上：

* 隐藏表示变化率：0.46%；
* 预测类别变化率：3.6%，一个种子。

这些结果支持“当前隐藏表示通常较稳定”，但不足以把整个系统概括为无条件的 **near-exact end to end**。

这里仍有三个边界：

* 自然沉默单元依赖 margin 条件；
* 默认实现仍使用 waking update 前的活动构造掩码；
* readout 始终可塑。

而且，第 5 页已经明确：**最终测试关闭 suppression**。因此，定理保护的带 suppression 的当前计算，与最终准确率评估时的计算状态，也需要区分。

第 217 行的：

> “no replay update touches the units the present input uses”

字面上不准确。式（3）允许更新“沉默 presynaptic → 活跃 postsynaptic”的连接。保护的是这些更新在规定条件下对当前活动的影响，并非所有活跃单元的相关参数都不更新。

建议让摘要与 Discussion 都明确保留“固定当前输入与 suppression、满足相应条件”的限定。这样可以保留理论贡献，无需为了 workshop 强行增加部署系统实验。

**3. Readout-only 的结果有价值，但“at chance”和“entirely”应删除。**

第 6 页第 222–223 行写：

> “at chance (27.3 ± 15.1)”
> “the effect is hidden-layer consolidation entirely”

十分类的随机猜测水平约为 10%，`27.3 ± 15.1` 不宜直接称为 at chance。

更重要的是，**仅更新 readout 的变体表现很差，说明这种配置不足以恢复完整方法的表现；不能推出全部收益都来自隐藏层，或者 readout 的贡献为零。**

更稳妥的结论是：在当前设置下，readout-only replay 无法解释完整方法的收益，隐藏层 replay 更新对恢复其表现具有重要作用。

这已经足够回应上一轮质疑，不需要把因果结论写满。

**5. 成本说明更诚实了，但还需要改正一处计数，并收紧“affordable”。**

第 5 页第 198–200 行把低预算配置写为：

> “22% more, in 39× more updates of 16”

实际上，两种低预算方案分别是：

| 方案                |   更新次数 | Batch size | 相对 night 更新次数 |
| ----------------- | -----: | ---------: | ------------: |
| 每步 replay 8 个样本   | 18,760 |          8 |         39.1× |
| 每两步 replay 16 个样本 |  9,380 |         16 |         19.5× |

所以，“39× updates of 16”对应的是默认高预算方案，不能同时描述这两种低预算配置。样本预算更准确的措辞是 **约 1.22×，即多约 22%**。

新增 wall-clock 也改变了效率结论：默认方法 6.6 分钟，night 0.6 分钟，按报告数值约为 **11 倍总训练时间**。这不否定移除集中离线阶段的价值，但第 304–305 行“an online system can afford”尚缺少明确的响应时间要求来支撑。

现有证据支持的是：**以更高总计算成本，将集中巩固分散到流处理步骤之间。** CPU 实现尚未优化可以作为限制说明；稀疏推理的能耗代理应与持续更新成本分别讨论。
